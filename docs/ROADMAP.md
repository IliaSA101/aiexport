# План выпусков

Что входит в какую версию и в каком порядке делается. Требования — `docs/ТЗ.md`,
структура пакетов и обоснования решений — `docs/ПЛАН_v1.md`.

## Версии

| Версия | Что входит | Состояние |
|---|---|---|
| **0.1** | выгрузка из нескольких папок, режимы «полностью» и «только дерево» на источник, счёт токенов с зонами бюджета, веб-интерфейс, отчёт о пропущенном с причинами | код готов, собирается Go 1.26.9 по директиве `toolchain`; готовится выпуск |
| 0.2 | профили с историей в интерфейсе, маски, `.aiexport.yaml`, portable-режим, отчёт о пропусках в UI, автодекодирование однобайтных кодировок | |
| 0.3 | режим скелета; дерево расхода токенов по папкам и кэш | |
| 0.4 | сканер секретов, доступ по сети, сверка промта с бандлом | |

**Тесты для 0.1 не наращиваются специально.** Существующие зелёные и остаются, новый код
по-прежнему идёт с тестом, но добирать покрытие ради первой версии смысла нет: она проверяется
на реальных папках.

**Сканер секретов отложен сознательно.** В выгрузку по умолчанию не попадает ничего, что закрыто
`.gitignore`, а неотменяемый запрет на `.git` стоит до всех остальных правил. Если дойдёт до
выгрузки чужих проектов, денylist имён (`.env*`, ключи, сертификаты) вернётся в ближайшую версию:
он дешёвый.

## Этапы

Каждый этап заканчивается чем-то запускаемым и проверяемым на реальных данных — не на фикстурах.
Проверочный полигон: репозиторий на 12 531 файл и 110 МБ с вложенными `.gitignore` в четырёх
каталогах, плюс крупный фронтенд-проект для замеров экономии токенов.

| № | Этап | Пункты ТЗ | Критерий готовности | Статус |
|---|---|---|---|---|
| −1 | Оснастка: проверки, линтеры, документы | — | прогон проверок зелёный, ноль предупреждений | **07.10.2026** |
| 0 | Каркас: флаги, логирование, `--version`, корректное завершение | — | `aiexport --version` отвечает; кросс-сборка под Linux собирается и запускается | **07.10.2026** |
| 1 | Ядро: обход, `.gitignore`, определение бинарного, план, Markdown с манифестом | 1, 2, 9, 10 | на полигоне нет `vendor` и `node_modules`, а файл конфигурации в глубине дерева попадает в выгрузку **с содержимым**; оракул-тест движка ignore против git зелёный | **20.10.2026** |
| 2 | Токены: `o200k_base`, зоны бюджета, дерево по папкам, кэш, доля каждого корня | 4 | цифры сходятся со сторонним счётчиком на том же наборе | критерий закрыт 20.10.2026; осталось дерево по папкам, кэш и доля корня |
| 3 | Мультикорень и веб-интерфейс: путь, подпись, порядок, превью | — | бандл из двух разных корней, подписи и пути читаются | **20.10.2026** |
| 4 | Маски, `.aiexport.yaml`, профили, portable, отчёт о пропусках в UI | 3, 5 | профили сохраняются атомарно; отчёт показывает причину по каждому исключению | |
| 5 | Режимы на путь: полностью, скелет, только дерево | 7 | воспроизвести расчёт из ТЗ: втрое меньше токенов на большом фронтенд-проекте | частично: `full` и `tree` готовы 20.10.2026, скелет — отдельной спекой |

| 8 | Сверка промта с бандлом | 11 | спека `003-prompt-check.md` | |

**Почему веб-интерфейс на третьем месте, а не по приоритету ТЗ.** Всё остальное в списке —
понятная обработка файлов с предсказуемой сложностью. Пикер и мультикорневой сценарий —
единственное место с настоящей неизвестностью, а рискованное трогают рано, пока переделывать
дёшево.

## v2

- `--since main` / `--since HEAD~5` — только файлы из диффа.
- `--clipboard` — сразу в буфер обмена.
- `--split-output` — нарезка под вставку в чат по частям, первым куском манифест.
- Режим MCP-сервера.
- AST-скелет через tree-sitter. Тянет cgo, а это ломает «один статический бинарник» —
  ключевое отличие от аналогов, поэтому сначала развилка: обычный скелет из 0.3 может закрыть
  потребность целиком.

## Идеи без приоритета

- `docs/ARCHITECTURE.md` — когда структура устоится; раньше это фантазия.
- Вставка большого файла в чат текстом против приложения файлом — эксперимент о том,
  как модель читает то и другое. Любой исход даёт правило, но это не код.
