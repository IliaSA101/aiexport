# Выпуск версии

Чек-лист для каждой версии, которая уходит на GitHub. Проходить целиком, по порядку.

## 1. Версия

Единственный источник — флаг сборки, файла-носителя нет:

```
-ldflags "-X main.version=0.1.0"
```

Если флаг не передан, `main.buildVersion()` берёт версию из метаданных модуля (их пишет сам `go`), а при их отсутствии отдаёт `(dev)`. То есть рассинхрона между «версией в файле» и «версией в бинарнике» быть не может по построению.

Семвер: `0.X.0` — новая функциональность, `0.X.Y` — исправления. Версия видна по `aiexport --version` и пишется в лог при запуске.

Строку в «Что нового» (внизу) писать для человека, без технических слов.

## 2. Проверки — всё зелёное, ноль предупреждений

```
powershell -ExecutionPolicy Bypass -File scripts/check.ps1 -Race -Vuln -Cross
```

- `-Race` требует gcc (WinLibs, уже стоит). `CGO_ENABLED=1` только на этот шаг.
- `-Vuln` — `govulncheck`, нужен интернет за свежей базой уязвимостей.
- `-Cross` — сборка под linux и darwin с `CGO_ENABLED=0`. Если упала — в зависимости затащили cgo, и «один бинарник под три ОС» больше не выполняется.

QA по `docs/QA.md`: пункты, затронутые циклом; консоль браузера без ошибок и предупреждений. Если менялся формат профилей — открыть файл профилей прошлой версии и убедиться, что он читается.

## 3. Сборка трёх бинарников

```
$env:GOTMPDIR = "$PWD\.gotmp"
$env:CGO_ENABLED = "0"
$v = "0.1.0"
foreach ($t in 'windows/amd64', 'linux/amd64', 'darwin/arm64') {
    $os, $arch = $t -split '/'
    $ext = if ($os -eq 'windows') { '.exe' } else { '' }
    $env:GOOS = $os; $env:GOARCH = $arch
    go build -trimpath -ldflags "-s -w -X main.version=$v" -o "dist/aiexport-$v-$os-$arch$ext" ./cmd/aiexport
}
$env:GOOS = $null; $env:GOARCH = $null; $env:CGO_ENABLED = $null
```

Версия стоит в имени файла: бинарники выкладываются в Release, и по имени видно, какой у кого. `-s -w` убирают таблицу символов и отладочную информацию — бинарник меньше, на поведение не влияет.

`-trimpath` обязателен, и не ради размера: без него в бинарник попадают полные пути машины
сборки — каталог проекта и имя пользователя. Бинарник выкладывается публично, то есть это утечка.
Проверять после сборки, подставляя своё:

```powershell
# каталог сборки и имя пользователя не должны встречаться ни разу
strings dist/aiexport-… | Select-String -SimpleMatch (Get-Location).Path | Measure-Object -Line
strings dist/aiexport-… | Select-String -SimpleMatch $env:USERNAME | Measure-Object -Line
```

```bash
strings dist/aiexport-… | grep -cF "$(pwd)"
strings dist/aiexport-… | grep -cF "$(whoami)"
```

Искать именно пути машины, а не имя владельца репозитория: оно входит в путь модуля
`github.com/IliaSA101/aiexport` и честно встречается в бинарнике сотни раз — проверка на него
даёт ложную тревогу (проверено 20.10.2026: 176 совпадений, все до одного — имя модуля).

## 4. Смоук собранного бинарника руками, ~3 минуты

Проверять именно собранный файл, а не `go run`: отличия бывают ровно в том, что вшивается через `embed.FS`.

1. `aiexport --version` — версия та, что собирали.
2. Двойной клик по `.exe`: поднялся сервер, открылся браузер, форма работает, консоль чистая.
3. Основной сценарий целиком: два разных корня с подписями → превью токенов → сборка → проверить, что в выгрузке есть манифест, нет `vendor`/`node_modules`, а отчёт о пропусках непустой и честный.
4. Второй запуск при уже поднятом первом: внятное сообщение, а не `bind: address already in use`.
5. Headless: `aiexport --config .aiexport.yaml --out export.md` — файл на месте, UTF-8 без BOM, переводы строк LF.
6. Лог: строка «запуск, версия X», ошибок и предупреждений нет.
7. Linux-бинарник запустить в WSL: `--version` и headless-прогон.

## 5. Публикация

- Коммиты уходят в `main` обычной историей (не сжимаем: репозиторий публичный, история — часть проекта).
- Тег `v0.1.0`, GitHub Release с тремя бинарниками и строкой «Что нового».
- `README.md` на GitHub — главная инструкция для читателя. Отдельного документа для пользователя нет: пользователь здесь технический.
- **Push и публикация — только после явного «да» от пользователя.** Коммиты делает он сам.
- Неподписанный `.exe`: при первом запуске Windows SmartScreen предупредит — «Подробнее» → «Выполнить в любом случае». Упомянуть в Release notes.
