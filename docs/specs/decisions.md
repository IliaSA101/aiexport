# Журнал развилок

Решения, принятые по ходу работы без остановки владельца. Формат: вопрос, варианты,
выбор, почему. Владелец проверяет по итогам цикла и может развернуть любое.
Вопросы с меткой `[владелец]` сюда не попадают — они задаются напрямую.

## Цикл 1 (20.10.2026)

### 1. Офлайн-словарь для счёта токенов

Вопрос: `tiktoken-go` по умолчанию скачивает словарь BPE из интернета — это ломает
«один самодостаточный бинарник». Брать ли библиотеку вообще.

Варианты: (а) `tiktoken-go` + `tiktoken-go-loader` с вшитым словарём; (б) оценка
«символы / 4» без зависимости; (в) своя реализация BPE.

Выбор — (а). Проверено прототипом 20.10.2026: `SetBpeLoader(NewOfflineLoader())` перед
`GetEncoding("o200k_base")` считает без сети, словарь вшивается в бинарник. Граф
зависимостей маленький: `dlclark/regexp2`, `google/uuid`. Вариант (б) отвергнут потому,
что все пороги зон и все цифры проекта получены на o200k_base — расхождение в 10–15 %
обесценивает светофор, ради которого счётчик и делается.

Замерено 20.10.2026: словарь добавляет к бинарнику около 12 МБ. Каркас без него весил 2,2 МБ,
сборка цикла 1 — **14,1 МБ** с `-trimpath -s -w` (16,2 МБ без них). Решение — принять: «один
самодостаточный бинарник» остаётся выполненным, 14 МБ для скачивания нормальны, а альтернатива
(скачивать словарь при первом запуске) ломает главное требование ради экономии, которая никому
не мешает. Если владелец сочтёт иначе — развилка открывается заново, менять придётся только
`internal/tokens`.

### 2. Пороги зон токенов (развилка 2 из плана v1)

Вопрос: где границы зелёной, жёлтой и красной зоны.

Выбор — зелёная ≤ 80 000, жёлтая ≤ 120 000, красная выше. Это предложение из плана v1,
владелец его не оспорил, а цикл без порогов не собрать. Целевой бюджет из `00_КОНТЕКСТ.md`
— около 100 000 токенов, то есть жёлтая зона начинается заметно раньше бюджета и
оставляет место на промт и ответ. Пороги вынесены константами в один пакет: менять —
одна строка, а не поиск по коду.

### 3. Секция «что сознательно не включено» (развилка 3 из плана v1)

Вопрос: формально это расширение ТЗ — брать ли в v1.

Выбор — брать. Стоит почти ничего (генерируется из `Plan`, который и так строится), а
лечит реальный класс ошибок: без неё модель считает отсутствующий каталог несуществующим
и предлагает создать заново (`00_КОНТЕКСТ.md` §9).

### 4. Режим «скелет» не входит в цикл 1

Вопрос: ТЗ п. 7 требует три режима на источник — полностью, скелет, только дерево.

Выбор — в цикле 1 делаются `full` и `tree`, `skeleton` переносится. Реальная задача
владельца («одну папку полностью, другую структурой») закрывается двумя режимами, а
скелет — это регулярки по объявлениям, разные для каждого языка, с отдельным разбором
и отдельными тестами. Смешивать его в цикл, который и так сводит три этапа бэклога,
значит отложить работающий инструмент ради фичи, которая сегодня не нужна.

### 5. Разделитель в `--src`

Вопрос: как передать тройку «режим, подпись, путь» одним флагом.

Выбор — `--src "full|Подпись|D:\путь"`, разделитель `|`. Двоеточие отпадает: в путях
Windows оно стоит после буквы диска. Повторяемый флаг вместо позиционных аргументов —
порядок флагов задаёт порядок секций в бандле, и это видно в самой команде.

### 6. `Plan` не хранит содержимое файлов

Вопрос: рендер читает файлы повторно или содержимое кэшируется в плане.

Выбор — не хранить, читать повторно. На рабочем полигоне 12 500 файлов и 110 МБ:
держать это в памяти нечем оправдать, а повторное чтение попадает в кэш ОС. Цена —
окно между планом и рендером, в котором файл может измениться; при расхождении размера
рендер пишет пометку в бандл, а не молчит.

### 9. Go 1.26.9 — директивой `toolchain`, а не установкой

**Вопрос.** `govulncheck` 20.10.2026 нашёл в стандартной библиотеке Go 1.26.7 одиннадцать
уязвимостей, которые наш код реально вызывает (`net/http`, `net/textproto`, `crypto/tls`, `os`).
Все исправлены в 1.26.9. Мы поднимаем HTTP-сервер на машине пользователя, поэтому это блокер
выпуска 0.1. Пункт был вынесен владельцу как требующий установки ПО.

**Что изменилось.** Тулчейн `go1.26.9` уже лежит в модульном кэше машины
(`C:\Users\<пользователь>\go\pkg\mod\golang.org\toolchain@v0.0.1-go1.26.9.windows-amd64`) — его скачал
соседний проект. То есть установка и обращение к сети больше не нужны: достаточно директивы
`toolchain go1.26.9` в `go.mod`, и `go` сам соберёт нужной версией.

**Варианты.** (а) ждать, пока владелец поставит Go 1.26.9 системно — выпуск стоит;
(б) директива `toolchain` в `go.mod`; (в) выпустить на 1.26.7 и обновиться позже.

**Выбрано (б).** Суть вопроса к владельцу была про установку ПО, а её не требуется: это
штатный механизм Go, запись обратима одной строкой и делает версию сборки воспроизводимой —
у любого, кто соберёт проект, возьмётся ровно 1.26.9, а не «что стоит на машине». Вариант (в)
отпадает: отдавать другим бинарник с известными дырами в сетевом коде нельзя.

**Проверено.** Сборка под 1.26.9 проходит, `govulncheck ./...` — **No vulnerabilities found**
(было 11), полный `check.ps1 -Race -Vuln` зелёный за 105 с, кросс-сборка под Linux собирается.
Релизный бинарник пересобран: 14,9 МБ с `-trimpath` и `-s -w`.

**Цена.** На машине без этого тулчейна первая сборка скачает его из сети (штатное поведение
`GOTOOLCHAIN=auto`). Это про сборку, а не про работу инструмента: требование «ноль внешних
зависимостей» относится к готовому бинарнику и не нарушается.

### 10. Правила путей Windows проверяются только на Windows — чиним тесты, а не валидатор

**Когда.** 21.10.2026, после переезда на Ubuntu. Решение владельца.

**Вопрос.** На Linux падают два теста `internal/server`: `TestBrowseRejectsServicePaths` ждёт
отказа на `//server/share` и `/\server\share`, `TestExportDownloadAndBadOut` — на
`\\server\share\b.md`. Чинить тесты или валидатор?

**Варианты.** (а) развести тесты по платформам, как уже сделано в `paths_test.go`;
(б) заставить `internal/paths` отбивать эти формы на всех ОС ради симметрии.

**Выбрано (а).** На POSIX `//server/share` — законный абсолютный путь, а не сетевой ресурс,
а `\\server\share\b.md` — обычное имя файла с обратными слэшами. Вариант (б) запретил бы
пользователю Linux нормальные пути ради правила, которое имеет смысл только в Windows, —
и ровно там инструмент теперь и живёт на второй машине. Разделение в `paths_test.go`
через `runtime.GOOS` уже есть, тесты сервера просто его не повторили.

**Побочное.** Второй тест пишет по непроверенному пути и оставляет в `internal/server/`
файл с именем `\\server\share\b.md` — чинится там же: вывод в `t.TempDir()`.
