# Спеки

Спека — короткий документ «что должно получиться», который пишется **до** кода. Нужна она не всегда.

## Когда спека нужна, а когда нет

**Нужна** там, где есть поведение и выбор: веб-UI и мультикорневая сборка, режимы «полностью / скелет / только дерево», сверка промта с бандлом, формат вывода. То есть там, где можно сделать по-разному и переделка стоит дорого.

**Не нужна** там, где требования уже расписаны в `docs/ТЗ.md` до уровня проверяемых критериев: обход дерева, `.gitignore`, определение бинарности, подсчёт токенов. Писать спеку для них — переписывать ТЗ своими словами.

**Не нужна** для багов и мелких правок. Баг описывается в задании исполнителю.

## Правила

- Имя: `NNN-kebab-name.md`, номера по порядку, не переиспользуются.
- Статус в шапке: `draft` → `accepted` → `done`. Поведение изменилось — сначала правится спека, потом код.
- **Основной файл ≤ 15 КБ**: зачем, сценарии, критерии приёмки, что не входит, открытые вопросы. Техрешение выносится в `NNN-имя/design.md`, разбор референсов и отвергнутые варианты — в `NNN-имя/research.md`. Исполнитель читает основной файл и `design.md`: так агент получает нужные части, а не сорок килобайт целиком.
- Критерии приёмки проверяемые: что нажать и что должно получиться. По ним работает QA, они же становятся именами тестов.
- Открытые вопросы к пользователю держать списком в спеке, а не задавать по одному в переписке.

Шаблон — `_template.md`.
