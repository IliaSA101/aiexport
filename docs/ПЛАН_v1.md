## Структура пакетов

```
cmd/aiexport/          main: флаги, выбор режима, slog, graceful shutdown
internal/
  model/               BundleSpec, Source, Plan, FileEntry — общие типы, ничего не импортирует
  ignore/              движок правил: .gitignore, дефолты, пользовательские глобы
  scan/                обход ФС, сбор кандидатов, детект текст/бинарь
  tokens/              o200k_base, зоны, дерево токенов, кэш
  secrets/             правила gitleaks + матчер
  skeleton/            режимы full / skeleton / tree
  bundle/              Plan → Markdown, манифест, порядок, отчёты
  probe/               сверка промта с бандлом
  config/              .aiexport.yaml, профили, portable-режим
  server/              HTTP API + embed веб-UI
web/                   index.html, ES-модули, CSS — вшиваются через embed.FS
docs/  testdata/  scripts/
```

`pkg/` в v1 пустой: это обещание стабильного публичного API, а обещать пока нечего. `internal/` физически запрещает внешний импорт и позволяет менять сигнатуры без последствий. Наружу вынести можно в любой момент, вернуть обратно — нет.

`model/` отдельным пакетом, потому что в Go нет циклических импортов. Если `Plan` живёт в `bundle`, то `scan` импортирует `bundle`, а `bundle` уже не сможет импортировать `scan`. Пакет с голыми типами и нулём зависимостей развязывает это раз и навсегда.

## Ключевые решения

### Разделение «план» и «рендер»

Сборка в два прохода. Первый строит `Plan`: все файлы с решением по каждому — включён или исключён, каким правилом, каким режимом, сколько токенов. Второй рендерит `Plan` в Markdown потоком в `io.Writer`.

Одна структура закрывает четыре требования ТЗ: счётчик токенов с зонами (п. 4) — сумма по `Plan`; отчёт о пропусках (п. 5) — фильтр по `Plan`; манифест в шапке (п. 9) физически требует знать список до записи первого файла; превью в UI — это `Plan` без второго прохода.

### Свой ignore-движок, не библиотека

Готовые (`sabhiram/go-gitignore`, `go-git/.../gitignore`) отвечают `bool`. Нам нужно три вещи, которых в этом API нет:

1. **Какое правило исключило файл** — требование п. 5 ТЗ.
2. **Вопрос «исключён ли весь каталог» до рекурсии в него.** Пофайловый опрос всё равно обойдёт 12 117 записей `vendor` + `node_modules`; отсечение каталогом (`fs.SkipDir` в `filepath.WalkDir`) — разница между секундой и минутой.
3. Один движок на три источника правил (`.gitignore`, дефолты, глобы из UI) с единообразной причиной исключения.

Цена — около 200 строк и понимание семантики: порядок правил, последнее совпадение выигрывает, `!` — отрицание, `/` в начале якорит к корню, `/` в конце матчит только каталоги, вложенные `.gitignore` переопределяют родительские.

Проверка — оракул-тестом против `git check-ignore --verbose` на реальных деревьях: git здесь эталонная реализация и сам выдаёт сработавшее правило. Вызывать `git check-ignore` в продакшене отвергнуто: требует установленного git, не работает вне репозиториев и на чужих корнях (а мультикорень — вся суть инструмента), стоит процесс на запуск.

### Пути при мультикорневой сборке

Абсолютные — шумно, светят структуру машины, ломают копипаст. Относительные к общему корню — общего корня в мультикорне нет. Берём относительные к своему `Source` с префиксом-подписью: `[Модуль CRM] lib/handler.php`. Модель должна видеть, что это разные деревья, иначе начнёт достраивать несуществующую общую иерархию. Подпись из UI работает дважды: человеческий заголовок секции и разрешение коллизий.

### Windows-специфика — и диагноз старого бага

В `00_КОНТЕКСТ.md` §1 висит гипотеза, что исключения в старом скрипте не срабатывали из-за несовпадения регистра и разделителей при вычислении относительного пути.

Правило на весь проект: внутри всё нормализовано в слэш-пути, глобы матчатся только по `/`, сравнение путей на Windows регистронезависимое, разделители ОС появляются только в момент вызова `os.*`. Для чтения внутри корня — `os.Root` (Go 1.24+): доступ, гарантированно не выходящий за корень через симлинки. Симлинки на каталоги не разворачиваем — git тоже не разворачивает, иначе первый цикл вешает обход.

### Детект бинарников с поправкой на Windows

База как в git: NUL-байт в первых 512 байтах. Но на Windows встречаются UTF-16 файлы (вывод PowerShell, старые конфиги), и git считает их бинарными — мы потеряли бы содержимое тем же тихим способом, из-за которого отказались от whitelist расширений. Поэтому: BOM UTF-16 в начале → декодировать в UTF-8 (`unicode/utf16` из stdlib, зависимость не нужна), и только потом проверять на NUL.

### Лимит размера файла выводится из бюджета

Дефолт 256 КБ: это ≈65 000 токенов, две трети целевого бюджета в 100k из §4 контекста. Один такой файл съедает сессию. Отброшенные по лимиту попадают в отчёт п. 5 списком с размером.

### Скелет признаётся, что он скелет

Режим «скелет» (регулярки: docblock + строка объявления) врёт на краях. Выведенный как обычный файл, он создаёт тот же класс тихой потери, что whitelist расширений: модель уверена, что видела код целиком, и делает выводы из отсутствия вырезанного. Поэтому в каждом скелетном файле первой строкой явная пометка, что тела удалены. То же для «только дерево» — секция «файлы существуют, содержимое не включено намеренно».

### Секция «что сознательно не включено»

Сверх ТЗ. В §9 контекста зафиксировано: главная польза русской шапки в repomix оказалась не в языке, а в том, что появилось место, где явно объявлены намеренные исключения — иначе модель считает отсутствующий `config/` несуществующим и предлагает создать заново. Генерируется автоматически из `Plan`, отфильтрованного по причине исключения. Ставится в конец, вместе с полем свободных инструкций: п. 6 ТЗ говорит, что конец файла — лучшая позиция для внимания.

### Безопасность веб-режима — три вещи, а не одна

ТЗ говорит «loopback + токен», этого мало.

- **DNS rebinding.** Любой сайт в браузере пользователя может обращаться к `127.0.0.1:8471`. Лечение — проверка заголовка `Host`: только `127.0.0.1`/`localhost` с нашим портом.
- **Ограничение корней** (`--allow-root`): иначе токен означает «читать весь диск».
- **Сравнение токена** через `crypto/subtle.ConstantTimeCompare`, а не `==`.

## Зависимости

| Библиотека | Зачем | Почему не альтернатива |
|---|---|---|
| `bmatcuk/doublestar/v4` | глобы с `**` | `filepath.Match` из stdlib матчит один сегмент, `**` не умеет. Свой парсер глобов — работа без выгоды |
| `pkoukk/tiktoken-go` | токены `o200k_base` | Оценка «символы/4» даёт ±10–15%; все цифры проекта и пороги зон получены на o200k_base, расхождение обесценивает светофор |
| YAML-парсер (`goccy/go-yaml`) | `.aiexport.yaml`, профили | JSON из stdlib — ноль зависимостей, но конфиг правится руками и комментарии в нём нужны. `gopkg.in/yaml.v3` заморожен |

**Риск, который снимается до записи в `go.mod`:** `tiktoken-go` по умолчанию скачивает словарь BPE из интернета при первом запуске, что противоречит «один самодостаточный бинарник». Есть `tiktoken-go-loader` с офлайн-словарём, вшиваемым в бинарник. Проверить до добавления зависимости; если офлайн-путь не работает — вернуться к пользователю с развилкой, а не тащить сетевой вызов молча.

Не берём: `go-git` (гигантский граф ради одной команды `git log --name-only`; вызываем бинарник `git`, нет git — фича молча отключается), роутеры `chi`/`gin` (`net/http.ServeMux` с Go 1.22 умеет паттерны с методом), пакет для открытия браузера (три строки `exec` под три ОС).

Фронтенд — vanilla JS без сборки, как требует ТЗ. Цена честная: пикер, порядок и профили на голом JS — около тысячи строк, менее приятных, чем на фреймворке. Обмен сознательный: сборка фронта убивает «клонировал и собрал одной командой».

## Чего не делаем в v1

AST-сжатие (`00_КОНТЕКСТ.md` §3). Docker и dev-контейнер для разработки. Путь через wazero для tree-sitter. Расчёт на окно 1M. Список v2 — в `docs/ROADMAP.md`.

## Открытые развилки

1. **Секреты: библиотека gitleaks или только её правила.** ТЗ говорит «подключается библиотекой». Склоняюсь взять из gitleaks только `gitleaks.toml` (правила — данные под MIT, регулярки в RE2, совместимом с Go) и написать свой матчер на ~150 строк: нужна причина срабатывания для отчёта, нужен контроль скорости на 12k файлов, и не хочется тащить CLI-приложение с viper/cobra как библиотеку. Это расхождение с ТЗ — решает пользователь. Перед решением замерить реальный граф зависимостей библиотеки.
2. **Пороги зон.** Предложение: зелёная ≤80k, жёлтая 80–120k, красная >120k, настраиваемые.
3. **Секция «что сознательно не включено» — берём в v1?** Считаю, что да: почти бесплатно, лечит реальный класс ошибок. Формально расширение ТЗ.
